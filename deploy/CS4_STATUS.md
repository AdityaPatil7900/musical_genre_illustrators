## Caveat on "image generation"
In both deployments the remote image call (`Qwen/Qwen-Image` via HF Inference)
failed, so the app used its built-in **static fallback artwork** (the response
says so in the "Image generated by" field). Genre classification and the LLM
prompt step work. Likely cause: the HF token/account has no inference
provider access or credits for that model. Check this before claiming live
image generation in the report.

## Blocked: AWS
- The credentials in use are for the IAM **user** `ML_dev`
  (`arn:aws:iam::324117660301:user/ML_dev`), not a role, with long-term keys
  (no session token). It is denied on iam:GetRole, ec2:DescribeVpcs,
  ecr:DescribeRepositories, ecs:ListClusters, elasticloadbalancing,
  secretsmanager:ListSecrets, ec2:DescribeSubnets and logs:DescribeLogGroups.
- So the default-VPC check, the role check, and `deploy_ecs.sh` could not run.
  This is not a script bug and I could not fix it from here.
- You need to: ask the instructor/TA what the intended AWS access is, or use
  a different AWS login (for example a Learner Lab, which gives three temporary
  values) that can create ECR/ECS/ALB resources. Then run
  `EXISTING_EXEC_ROLE_NAME=<role> ./deploy/aws/deploy_ecs.sh` if a role is
  provided, or the script unmodified otherwise.

## Blocked: GitHub Action
`gh` is not installed or authenticated, so I could not set repo secrets. In
GitHub: Settings -> Secrets and variables -> Actions -> New repository secret:
- `GCP_PROJECT_ID` = `cs553-group12-cs4`
- `HF_TOKEN` = your Hugging Face token
- `GCP_SA_KEY` = contents of a key made with:
  `gcloud iam service-accounts keys create key.json --iam-account=github-deployer@cs553-group12-cs4.iam.gserviceaccount.com`
  then paste key.json and delete the file.
Then run it from the Actions tab: select the workflow and click "Run workflow"
(workflow_dispatch is enabled), or re-run the failed run.
