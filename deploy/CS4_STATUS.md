## GCP Cloud Run -- project cs553-group12-cs4, us-central1
Modifications needed (in `deploy/gcp/deploy_cloudrun.sh`, mirrored in
`.github/workflows/deploy-cloudrun.yml`):
1. **Secret access.** First deploy failed: "Permission denied on secret ...
   for Revision service account <project-number>-compute@developer
   .gserviceaccount.com". New projects no longer give the default compute
   service account Secret Manager access. Fix: bind
   `roles/secretmanager.secretAccessor` on `hf-token` before deploying.
2. **Request hang / startup crash.** The first request ran until Cloud Run's
   300 s timeout. Logs showed Gradio's launch-time localhost self-check
   failing ("When localhost is not accessible, a shareable link must be
   created") and the instance exiting. The same image answered in about 3 s
   locally and about 8 s on Azure. Fixes: `--execution-environment=gen2`,
   `--no-cpu-throttling` (CPU always allocated), `--memory=4Gi` (was 2Gi),
   and `NO_PROXY=localhost,127.0.0.1`. In testing, the revision with the
   CPU/memory/NO_PROXY changes still hung; switching to gen2 is what made
   requests succeed, so gen2 is the fix that resolved the hang. The other
   three were applied for the startup crash and were not tested separately.
3. Service account `github-deployer@cs553-group12-cs4.iam.gserviceaccount.com`
   created with Artifact Registry Writer, Cloud Run Admin, Service Account
   User and Secret Manager Admin (the last is needed because the workflow
   creates secret versions).

AdministratorAccess, so it cannot be fixed from inside the account.
